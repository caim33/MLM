文本侧也有严格合同

类型结构在当前 codebase 中的定位
QAquestion + options + answer当前 Qwen V / M / VM SFT、GRPO 与 benchmark 的正式文本类型
Caption逐帧、时间戳或 event 对齐文本辅助时序监督；转换成专用 prompt 后才能进入生成训练
一句话整段动作的一句摘要或短改写适合 motion-text 对齐/检索/短生成，不带选项和标准答案
详细描述多句、分阶段、身体/物体/时序细节适合长描述和推理；必须使用独立 prompt 与长度策略
Qwen branch 与文本类型是两条正交轴

V / M / VM 只表示非文本输入；QA / Caption / 一句话 / 详细描述 表示监督目标。现有正式 Qwen 清单是 QA，不能把 description 文件直接塞入 question/options 字段。各数据集的配对任务、覆盖率与统计口径见 多模态监督统计。

V / M / VM 是严格输入合同

Branch模型输入禁止出现用途
Vvideo + question/optionsmotion 路径与 motion anchor纯视频对照
Mmotion + question/optionsvideo纯运动表示能力
VM同 group 的 video + motion + question/options错配的 V/M视频与运动联合主实验
V+VM direct同 group 的 V 与 VM 各一条只剩单侧 branch成对训练/对照；不是第四种模态
含 M 的 branch 需要额外合同

M 与 VM 必须使用 263 维 NPY、显式 Mean/Std 和当前单一 <motion> anchor；V 发现 motion 字段应直接拒绝。完整数据集模态覆盖和交集数量见 数据统计页的监督矩阵。

默认入口已经更新为 qwen_qa/training

manifest.json 标记该包为 default。去重键是“归一化问题 stem + 无序 option 集合”，允许同一媒体对应不同问题；manifest 记录 train / validation / benchmark 的 question-signature overlap 均为 0。旧 views/recommended 和 views/extended_qtext 保留用于复现实验，不再是新训练默认入口。
