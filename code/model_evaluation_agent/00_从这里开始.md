## 固定工作顺序

1. 冻结本批 train、validation、benchmark、video、motion 和派生清单。
2. 对 15 个注册模型逐一完成资产、来源和数据泄漏审计。
3. 先对所有未阻塞模型完成本批次 fresh finetune。
4. 等 15 个模型全部成为 `finetune_complete` 或有证据的 `blocked` 后，
   才能开启 eval 阶段。
5. 只评估本批次新产生并记录 SHA-256 的 checkpoint/adapter。
6. 每个模型完成 smoke-1、smoke-8、smoke-32 后，才能跑正式 benchmark。
7. 输出逐样本结果、manifest、blocked 清单和统一汇总表。

历史 accuracy、prediction、adapter、baseline、option-score 诊断和代理模型
都不能进入新批次主结果。

## 新数据放置

每批数据建立：

`batches\<batch_id>\00_inputs\`

`<batch_id>` 必须包含数据版本或 hash，例如：

`qa500v2_20260730_a5a8cc6b`

服务器批次目录统一使用：

`/wangbenyou-sulongjie/Motion-r1/caimeng/MLLM/codex_runs/unified_model_eval/batches/<batch_id>`

大模型 base 权重不复制到批次目录。批次只记录 canonical 路径、revision 和
SHA-256，并把本批新产出的 finetune 权重写入
`02_finetune/<model_id>/`。
