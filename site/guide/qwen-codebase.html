文本侧也有严格合同

类型结构在当前 codebase 中的定位
QAquestion + options + answer当前 Qwen V / M / VM SFT、GRPO 与 benchmark 的正式文本类型
Caption逐帧、时间戳或 event 对齐文本辅助时序监督；转换成专用 prompt 后才能进入生成训练
一句话整段动作的一句摘要或短改写适合 motion-text 对齐/检索/短生成，不带选项和标准答案
详细描述多句、分阶段、身体/物体/时序细节适合长描述和推理；必须使用独立 prompt 与长度策略
Qwen branch 与文本类型是两条正交轴

V / M / VM 只表示非文本输入；QA / Caption / 一句话 / 详细描述 表示监督目标。现有正式 Qwen 清单是 QA，不能把 description 文件直接塞入 question/options 字段。完整定义见 四类文本监督，逐类数量见 Text 分类统计。

V / M / VM 是严格输入合同

Branch模型输入禁止出现用途
Vvideo + question/optionsmotion 路径与 motion anchor纯视频对照
Mmotion + question/optionsvideo纯运动表示能力
VM同 group 的 video + motion + question/options错配的 V/M视频与运动联合主实验
V+VM direct同 group 的 V 与 VM 各一条只剩单侧 branch成对训练/对照；不是第四种模态
含 M 的 branch 需要额外合同

M 与 VM 必须使用 263 维 NPY、显式 Mean/Std 和当前单一 <motion> anchor；V 发现 motion 字段应直接拒绝。完整数据集模态覆盖和交集数量见 数据统计页的模态矩阵。

凭据与远端安全

不要读取或打印连接文件。Secret 只能通过进程级环境变量注入；不得写进命令、YAML、日志、manifest 或回复。含个人路径的旧 GRPO 配置与运维脚本已移动到 legacy/refactor_snapshot/，禁止执行。

  • 不手工删除 GPU lease，不按模糊进程名批量 kill。
  • 历史 accuracy、prediction、checkpoint、proxy 和 option-score 不进入新主表。
  • 远端同步先 dry-run，禁止 --delete，只进入新的 staging 目录。
  • 任何 preflight/debug artifact 都不能 complete、evaluation 或 release。
