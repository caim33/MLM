MODALITY CONTRACT

先分清 V、M、VM，再细分文本监督

这里的“模态”描述的是单条模型样本实际输入什么，不等同于目录里有哪些文件。Qwen 的每条记录都包含文本，但 branch 名只描述视觉/运动输入组合；文本不能再统一写成一个含糊的 T。

V · VIDEO 视频模态

输入 MP4 + 文本问题。记录不得携带 motion 路径或 motion anchor；用于测纯视觉能力。

M · MOTION 运动模态

输入 263 维 motion NPY + 文本问题。必须绑定 Mean/Std，并使用当前单一 <motion> anchor。

VM · VIDEO + MOTION 视频运动联合模态

同一 logical group 的 MP4 与 NPY 同时输入；两者必须指向同一动作，不能随机拼接。

T · TEXT UMBRELLA 文本监督总类

T 只是上位概念，不是一个可直接混合的文本类型，也不是 Qwen branch 名；实际必须继续标注为 QA、Caption、Short 或 Long。

T 不是一种文本：必须拆成四类

本项目从现在起使用下面的语义合同。历史目录名仍可能叫 captions/，但目录名不决定训练语义；生成 manifest 时应写入明确的 text_type。

T-QA · QUESTION ANSWERING 问答 / 选择题

结构是 question + options + answer，目标是回答问题。当前 Qwen strict、extended_qtext 和 benchmark 都属于这一类。

T-CAP · LOCAL CAPTION 逐帧 / 分段 Caption

带 frame、时间戳或 event 边界，描述局部时刻或片段。它不是整段动作的一句话摘要。

T-SHORT · ONE-SENTENCE 一句话描述

序列级的一句或短语义摘要，不含问题、选项和答案，也不要求逐帧时间对齐。

T-LONG · DETAILED 详细描述

多句或结构化长文本，可包含整体概览、动作阶段、身体部位、交互对象与时序细节。

不要把四类文本直接拼进同一个训练池

至少在 manifest 中保留 text_type=qa|caption|short_description|detailed_description、source、sample_id 和时间粒度。若要混合训练，应先定义各类型的 prompt template、loss 目标与采样权重；其中 QA 是有标准答案的判别任务，其余三类主要是生成或对齐监督。
